API Gateway — Unified Documentation

Single entry point for all microservices. JWT verification, rate limiting, and zone-based routing happen here — services receive pre-authenticated requests.

Version 1.0.0
Base Path /api/v1
Auth Bearer JWT
IP Limit 100 req/min
User Limit 200 req/min
Gateway URL

🔐 Authentication

Gateway verifies JWT and injects user identity as headers. Services trust x-user-id and x-user-role — they never re-verify JWT.

Authorization: Bearer <your_jwt_token>
Gateway headers forwarded internally:  x-user-id  x-user-role  x-api-key
🔓 Public routes (no JWT needed): GET /stores, GET /stores/:id, GET /stores/pin-code/:pin, POST /administrators, POST /authorize-person/login, POST /authorize-person/verify-otp, POST /otp/send, POST /otp/verify

🗺️ Zone-Based Routing

All Zone Service routes need pin_code to select the correct instance:

PrioritySourceExample
1Query param?pin_code=700091
2Request body{"pin_code":"700091"}
3Headerx-pin-code: 700091
400 ZONE_NOT_FOUND — returned if pin_code is missing or not mapped to any registered zone instance.
